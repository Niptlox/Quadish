# Механизмы под сюжетную арку

Сюжет — `docs/STORY.md`. Здесь: что для него нужно в коде, что уже
готово, что сделано в этой итерации и что осознанно оставлено на потом.

## Принцип

Сюжет не должен превращаться в отдельную подсистему поверх игры. Всё, что
можно, переиспользуем: обучение уже умеет вести игрока по шагам, достижения
уже сохраняются, структуры уже расставляются по миру. Арка — это ещё один
потребитель тех же механизмов, а не новый движок.

## Инвентаризация: что уже было

| Механизм | Где | Годен для сюжета |
|----------|-----|------------------|
| Шаги с задачей, прогрессом, маркером цели | `units/Tutorial.py` (`Step`, `TutorialHints`) | Да — образец для глав арки |
| Состояние, сохраняемое с миром | `GameMap.tutorial_step`, `tutorial_state` | Да — тот же приём для арки |
| Достижения | `units/Achievements.py` | Да, готово |
| Структуры | `units/Map/Structures.py` | Годен, но расстановка была без биомов |
| Портал прибытия | `PortalMainGate` | Готов, уже играет завязку |
| Алтарь на старте | `structure_start` | Готов, нужен текст на нём |
| Зоны по глубине | космос / поверхность / пещеры / ад | Готово, задаёт вертикаль актов |

Главные дыры, которые пришлось закрыть в этой итерации: **структуры не
умели привязываться к биому** и **не было способа положить в мир читаемый
текст**.

## Сделано в этой итерации

### 1. Структуры из ASCII-схем — `units/Map/structure_builder.py`

Старые структуры заданы сырыми списками ячеек: 5 построек = 75 КБ
нечитаемых литералов. Добавить так десять новых — значит утроить файл и
гарантированно наделать опечаток.

Теперь структура пишется картинкой, а прочность подставляется из
`TILES_SOLIDITY` автоматически (её больше нельзя случайно разойтись с
ванильной):

```python
build_ascii([
    "..###..",
    "..#C#..",
    "..###..",
])
```

`.` — структурная пустота (рельеф не трогается, постройка вписывается в
склон), пробел — воздух (расчистить комнату). Легенда — в
`structure_builder.LEGEND`.

### 2. Привязка структур к биому и зоне

Раньше выбор структуры зависел только от зоны по Y (космос / поверхность /
ад), поэтому «структура для тундры» была невыразима. Теперь у структуры
есть необязательный список биомов, и в жеребьёвке участвуют только
подходящие. Структуры без списка биомов работают как раньше — в любом
биоме своей зоны.

### 3. Плита с надписью (тайл 300) — канал подачи сюжета

Блок, который можно прочитать правым кликом. Текст берётся из каталога
надписей по идентификатору, а не хранится в мире, поэтому:
* сохранения не распухают от текста;
* тексты можно править и переводить, не ломая старые миры;
* одна и та же плита в разных структурах может нести разные надписи.

Прочитанные надписи копятся в состоянии мира — это и есть «журнал».

### 4. Состояние арки, сохраняемое с миром

`GameMap.story_stage` (номер акта) и `GameMap.story_state` (словарь: что
прочитано, что найдено). Ровно тот же приём, что у обучения, — значит
работает с сохранениями без отдельного кода миграции.

## Что осознанно не сделано

Это подготовка, а не готовая арка. Не сделано намеренно:

* **Главы актов как шаги.** `units/Tutorial.py` — готовый образец, но
  выносить его общую часть в переиспользуемый модуль имеет смысл, только
  когда появится хотя бы один настоящий акт. Пока состояние есть, а
  сценария нет — переиспользовать нечего.
* **Журнал как экран.** Прочитанное копится, но отдельного экрана
  «Записи» нет. Его стоит делать вместе с первым актом, иначе он будет
  пустым.
* **Обломки корабля** (нужны для финала IV акта) — отдельная структура с
  особой расстановкой (одна на мир, а не по шансу). Текущий расстановщик
  так не умеет: он раскидывает постройки по весам в блоке 100×100 чанков.
  Уникальные структуры — отдельная задача.
* **Развилки выбора** (акт III, финал) — требуют не механизма, а решения
  по геймдизайну; в код лезть рано.
* **Перевод надписей с пробелами** (нарастающая полнота перевода) —
  тексты уже лежат отдельно от мира, так что добавляется потом без
  ломки сохранений.

## Известные ограничения расстановщика

Полезно знать до того, как строить на нём сюжет:

* Структура ставится на **случайной высоте** внутри блока 100×100 чанков —
  постройка может оказаться в толще камня или в воздухе. Для сюжетных
  структур, которые обязательно должны быть видны, этого недостаточно:
  нужна привязка к поверхности. Пока это обходится тем, что структуры
  используют `.` (пустоту) и не выглядят обрубленными в толще.
* Точки-триггеры постройки считались с ошибкой: у левого-нижнего угла
  вместо высоты подставлялась ширина, из-за чего у невысоких широких
  структур регистрировался не тот чанк. Исправлено.
* Уникальных структур (ровно одна на мир) расстановщик не поддерживает.

## Порядок дальнейших работ

1. Тексты надписей для акта I–II (контент, не код).
2. Привязка структур к поверхности — без неё сюжетные структуры находятся
   случайно.
3. Общий модуль шагов (вынести из `Tutorial.py`) + первый акт.
4. Экран журнала.
5. Уникальные структуры (обломки корабля) → финал.
